## ATS trap hit (new — not previously documented for Breezy HR)
First submit attempt failed with "Consent is required to apply" / "Your application contains errors" even though the Recruitment Privacy Notice checkbox was visibly checked (blue, checkmark visible) after setting it via the form_input tool. A follow-up real mouse click on the checkbox toggled it OFF (confirming the DOM was actually checked before), then a second real click toggled it back ON, and resubmitting succeeded immediately. Conclusion: Breezy HR's checkbox validation reads a React state that form_input's programmatic set did not update, even though the native checked property and visual rendering were correct — a real click is required for the required-consent checkbox specifically. Logged as a new ATS lesson for Breezy HR.
