## 9. ATS quirks worth remembering

- **Ashby + automated browser: first submit can be rejected with "Your application submission was flagged as possible spam."** Message itself invites resubmit; retrying once cleared it. Never attempt fingerprint or detection workaround.
- **Ashby error re-renders silently empty fields in React state while DOM still shows values** (hit on Zapier: Preferred First/Last + Email). Form looks complete, fails validation anyway. After any failed submit, clear via native value setter, retype real keystrokes, re-verify every field before resubmitting.
- Ashby location widgets often **country-level only** - "Venice" returns "No results", "Italy" works. Don't assume city granularity.
- Greenhouse / MyGreenhouse often autofills STALE `Prabhavit_CV-.pdf`; remove, re-upload canonical `Prabhavit_CV.pdf`.
- Lever: "Current location" field Google-places autocomplete clears unless select suggestion from dropdown (use "Venice, ITA").
- Ashby: `form_input` unreliable; use direct clicks / keystrokes. Some links return "Job not found".
- Teamtailor: decline non-essential cookies; phone widget defaults wrong country.
- **Workable now shows CLOUDFLARE TURNSTILE on some tenants** (Flosum and GoReel had it, SAP Fioneer didn't, per-tenant). Submit button hangs "Submitting..." with NO error text, in DOM indistinguishable from silent failure. ALWAYS screenshot before concluding anything. It's a CAPTCHA: fill everything, hand back for one tick.
- reCAPTCHA "I'm not a robot" hard stop; never solve, always hand back. (Invisible reCAPTCHA that passes on own fine.)
- Closed dropdowns excluding true answer (US-states-only residence, Poland-only domicile, German-proficiency with no "None") = hand back, never invent.
- Demographic sections almost always explicitly voluntary - leave entirely blank rather than guessing.
