## return already-verified rows in a fixed shape: title, company, url, eligibility
## wording, comp, posted date, basis)

   job-boards.eu.greenhouse.io (different companies on each) · jobs.smartrecruiters.com

   part-time) · <co>.jobs.personio.com (append ?language=en) · jobs.lever.co (noisiest:
   snippets lie about location, heavy with aggregators — always fetch before trusting).
2. One contract-vocabulary query with the literal words: "contract", "6-month contract",
   "12-month contract", "(Contract)", freelance, B2B, fixed-term, part time, fractional,
   day rate.
3. One stack-keyword query — his sharpest, least-crowded edge: n8n, AI agents, low-code,
   Bubble.io, Playwright, Zapier/Make/Tray.ai, workflow automation, RAG, Supabase.
4. Board fetches: euremotejobs.com (/job-region/remote-jobs-europe/, /remote-jobs-emea/,
   /jobs/remote-software-engineering-jobs/ — freshest feed, region strings distinguish
   Europe/EMEA/worldwide) · himalayas.app (/jobs, /jobs/countries/italy — SERIALIZE,
   it 429s under concurrency; per-job region restriction strings are gold; dates are
   non-chronological, read each row) · remoterocketship.com (?sort=DateAdded — SIGNAL
   ONLY, no direct-apply URLs: take company+title, find the original on the ATS) ·
   arbeitnow.com/api/job-board-api and remoteok.com/api (clean JSON; remoteok salary

5. LinkedIn: linkedin.com/jobs is robots-disallowed for fetch tools. ONLY if you have

6. Skip — tested dead/blocked: weworkremotely, welcometothejungle, landing.jobs, jobicy,

## Verify every survivor by loading it
- Normalise URLs first (strip Ashby ?embed=js, /application, ?utm_data, ?locationId;
  add ?language=en on Personio).
- From the loaded page pull: exact title, company, the ELIGIBILITY SENTENCE (not the
  word "Remote" in the title), comp/rate, posted date, seniority ask, employment vs
  contract.
- Greenhouse trap: a dead posting URL silently returns the whole board index — if a
  single-posting fetch describes many different jobs, the role is CLOSED. Drop it.
- Personio dead roles hard-404 (clean drop). Lever: read location from the page body.
- Ashby HTML often returns a JS shell ("enable JavaScript" / meta-title "Jobs") — that
  means the FETCH failed, not that the role closed. Read Ashby via its API instead.
- Cheapest verification — one JSON call verifies a whole org:
  Greenhouse: https://boards-api.greenhouse.io/v1/boards/<token>/jobs?content=true
  Ashby: https://api.ashbyhq.com/posting-api/job-board/<org>?includeCompensation=true
  Lever: https://api.lever.co/v0/postings/<co>?mode=json
  Workable: https://apply.workable.com/api/v1/widget/accounts/<subdomain>?details=true
  (apply.workable.com pages are an SPA — the API is the only readable route.)
- A negative from a truncated fetch/API read is NOT evidence a role is closed: get two
  independent reads that agree, or corroborate elsewhere. Burden of proof on the negative.
- A quiet omission beats a broken row.

## Score each survivor /100
role & track match 30 (actual responsibilities vs what he's done, not title) ·
eligibility & work basis 25 (Tier 1 full, Tier 2 most, Tier 3 fraction;
contractor-friendly US = Tier 1) · stack overlap 20 (named tools he shipped with —
n8n in a JD beats generic "Python required") · seniority realism 15 (target mid,
2–5 yrs or unstated; "Senior" OK at ~4–5 yrs with stack match; DROP Staff/Principal/
Head-of/people-management Lead/7+ yrs; contracts judged on deliverable scope, not
year count) · signal quality 10 (freshness, disclosed comp, 10–300-person startup/
scale-up, clear scope).
Use the full range — identical 82–88 scores carry no information.
Bands: 80+ apply this week · 65–79 solid · 50–64 backup · <50 omit (mention in
notes if interesting).
